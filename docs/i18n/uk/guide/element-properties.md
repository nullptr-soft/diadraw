# Редагування властивостей на полотні

Елемент — це не просто блок із назвою. Вид визначає, як його зображати, `tech` і `description` додають подробиці, `shape` вибирає контур, теги об’єднують елементи для оформлення, `style` змінює вигляд, а `prop` зберігає будь-які інші потрібні відомості:

```
model {
  db = container "Orders DB" tech "Postgres" shape cylinder tag "pii" prop "owner" "Ann"
}
```

Усе це можна записати в тексті, але не обов’язково. Виберіть на полотні один елемент, і його властивості з’являться на бічній панелі — в інспекторі. Виберіть один зв’язок (клацніть його лінію), й інспектор натомість покаже зв’язок; див. [Зв’язки](#звязки).

## Інспектор

Панель властивостей залишається біля полотна незалежно від вибору, тому вибір об’єкта не зсуває діаграму. Інспектор відображається, коли вибрано рівно один елемент чи один зв’язок. Якщо нічого не вибрано, панель показує [тему й стилі документа](styles-and-themes.md#тема-й-стилі-документа), а якщо вибрано кілька об’єктів — їхню кількість. Для елемента заголовком інспектора слугує його ідентифікатор.

| Поле | Що записує | Як заповнити |
| --- | --- | --- |
| Kind | вид після `=` | `container`, `database`, `person` тощо або бібліотечний `alias.kind` |
| Name | підпис у лапках | довільний текст; якщо порожньо, назвою є ідентифікатор елемента |
| Tech | `tech "…"` | довільний текст |
| Shape | `shape …` | базова фігура, наприклад `cylinder` чи `hexagon`, або бібліотечна фігура |
| Tags | по одному `tag "…"` на тег | через кому: `external, legacy` |
| Description | `description "…"` | довільний текст |
| Style | `style "…"` | пари `key=value`, розділені `;`: `fill=#dae8fc;stroke=#6c8ebf` |
| Properties | по одному `prop "…" "…"` на ключ | по одній парі `key=value` на рядок |
| Shared styles | застосовні блоки `style` | по одному `selector: key=value;…` на рядок (див. [стилі й теми](styles-and-themes.md)) |

У вебзастосунку Kind і Shape підказують вбудовані назви під час введення. Style приймає ті самі ключі, що й вбудований `style "…"` у тексті; їх перелічено в [довіднику DSL](../dsl.md#діаграми-довільної-форми).

### Засоби редагування в macOS, вебзастосунку та Linux

Більшість полів у цих застосунках редагується за допомогою елементів керування замість введення тексту. Кожен із них записує той самий текст, який описано для відповідного поля вище.

- **Kind, Shape і Tech** — списки для вибору, у які також можна ввести нове значення. Kind перелічує вбудовані види та види з бібліотек документа, Shape — базові й бібліотечні фігури (порожнє значення означає фігуру виду), Tech — уже використані в документі технології.
- **Tags** — поле з окремими мітками: введіть тег і кому; поле підказує теги, які вже є в документі.
- **Description** збільшується разом із текстом. Return починає новий рядок, а вихід із поля застосовує зміну.
- **Style** — візуальний редактор. Для елементів він дає змогу вибрати кольори заливки, лінії й тексту, ширину лінії, штриховий контур і заокруглення, непрозорість, розмір шрифту, жирний шрифт, курсив і підкреслення, вирівнювання та позицію підпису. Для зв’язків доступні колір, ширина, штрихування та візерунок лінії (крапки, штрих і крапка тощо), подвійна лінія, прямокутний маршрут, криві й заокруглені кути, початок і кінець (стрілки, ромби, кола, риски, «воронячі лапки», кожен зі зразком) та їхня заливка, колір і розмір підпису. Кожен параметр записує один ключ і не чіпає решту. Повернення типового значення (або ⓧ біля кольору) видаляє його ключ. Ключі без окремого елемента керування зберігаються в **Other** як `key=value;…`, а **Clear style** видаляє весь стиль.
- **Кнопки кольорів** відкривають палітру готових кольорів: відтінки сірого від білого до чорного, а далі світлі, яскраві й темні відтінки десяти тонів. Вибираючи однакові зразки, зручно дотримуватися узгоджених кольорів у різних елементах і діаграмах. **Custom…** відкриває системне вікно вибору довільного кольору, а **Default** видаляє ключ. Усі застосунки (macOS, Linux, веб) пропонують однакові зразки.
- **Properties** — таблиця ключів і значень: відредагуйте комірку, додайте рядок кнопкою + або виберіть рядок і вилучіть його кнопкою −.

Вебзастосунок має кілька особливостей: теги показуються плашками з × для видалення (Enter або кома додає введений тег, Backspace у порожньому полі видаляє останній); Style можна згорнути трикутником біля заголовка, щоб побачити натомість текст стилю; кожен рядок властивості має власний −, а Arrow для зв’язку — це три кнопки із зображеннями ліній. Доки ви не ввели ім’я зв’язку, поле Name сірим показує ідентифікатор, який DiaDraw виводить із його кінців.

У застосунку Linux (GTK) є ті самі засоби з незначними відмінностями у вигляді: Kind, Shape й Tech — поля з кнопкою ▾, яка перелічує варіанти, згруповані за бібліотекою. Теги показуються плашками з × для видалення, під ними є поле, яке додає тег за Enter або комою (його ▾ показує теги документа). Кожен рядок властивості має власний −. **Custom…** у палітрі кнопки кольору відкриває вікно вибору кольору GNOME.

### Застосування зміни

Значення поля застосовується, коли ви натискаєте Enter або переходите до іншого поля після зміни. Escape відновлює попереднє значення. Очищення Tech, Shape, Description або Style видаляє відповідну властивість; очищення Tags чи Properties вилучає всі теги чи властивості відповідно.

У полі опису Enter починає новий рядок: для застосування вийдіть із поля (або натисніть ⌘Enter / Ctrl+Enter у вебзастосунку). У таблиці властивостей Enter застосовує зміну до комірки.

Полотно показує опис під назвою й технологією дрібнішим шрифтом і збільшує висоту рамки, щоб він умістився (а для довгих рядків — і ширину, до 240 px, ромб чи еліпс — до 320 px). Довші рядки переносяться, а розриви й порожні рядки зберігаються. Кола, підписи поза фігурою (актори, `labelPosition`, `verticalLabelPosition`), малюнки з підписом усередині або з власним `style` і елементи, намальовані рамкою навколо своїх дочірніх, показують лише назву. Багаторядковий опис записується в текст блоковим рядком, рядок за рядком, з відступом під елементом:

```
model {
  db = container "Orders DB" tech "Postgres" description """
    Orders and their lines.

    Archived after two years.
  """
}
```

Так його можна писати і в тексті: `"""` відкриває й закриває опис, а спільний відступ рядків до опису не входить (див. [довідник DSL](../dsl.md#лексичні-правила)).

Кожна зміна — один крок скасування, спільний із текстовим редактором: ⌘Z з будь-якого боку скасує її.

## Зв’язки

Інспектор зв’язку має заголовок у вигляді рядка, як ви його записали б, наприклад `web -> db` чи `checkout = web -> db`, і такі поля:

| Поле | Що записує | Як заповнити |
| --- | --- | --- |
| Label | підпис у лапках | довільний текст; якщо поле порожнє, лінія без підпису |
| Tech | `tech "…"` | довільний текст |
| Arrow | `->`, `-->` чи `<->` | виберіть суцільну, штрихову або з наконечниками на обох кінцях |
| Name | `name =` перед лінією | ідентифікатор на кшталт `checkout`; якщо порожньо, він буде похідним |
| Tags | по одному `tag "…"` на тег | через кому: `async, legacy` |
| Style | `style "…"` | пари `key=value`, розділені `;`: `stroke=#c00;dashed=1` |
| Properties | по одному `prop "…" "…"` на ключ | по одному `key=value` на рядок |

Вибір стрілки застосовується відразу; інші поля — так само, як для елементів. Інспектор не показує кінців лінії: щоб перепідключити її, відредагуйте текст.

### Як назвати зв’язок в інспекторі

Поле Name містить ідентифікатор зв’язку, якщо ви його задали (див. [Іменовані зв’язки](relationships.md#іменовані-звязки)), і порожнє, якщо ідентифікатор утворено з кінців. Введення імені записує `name = ` перед лінією; очищення поля видаляє цей префікс. Лінія залишається вибраною під новим ідентифікатором, а всі `route "…"`, які вказували на старий, оновлюються, тому задані вручну точки згину зберігаються. Якщо лінії в такому документі

```
model {
  …
  web -> db "writes"
}

view main {
  route "web->db" via 200, 80
}
```

дати ім’я `calls`, зміняться два місця:

```
  calls = web -> db "writes"
  …
  route "calls" via 200, 80
```

Присвоєння чи видалення імені може змінити похідні ідентифікатори інших ліній між тими самими елементами, бо `#2`, `#3` враховують попередні неіменовані лінії. Їхні маршрути також оновлюються, тож жоден заданий вручну маршрут не втрачається. Ім’я, яке не є ідентифікатором або вже належить іншому зв’язку, відхиляється з поясненням у рядку стану.

## Як змінюється текст

Текст залишається першоджерелом, тож кожна зміна в інспекторі потрапляє до файла. При цьому інспектор записує якомога менше:

- змінене значення замінюється там, де ви його записали, тому `shape rect tech "React"` зберігає порядок при зміні технології, а нова стрілка замінює лише стрілку;
- очищена властивість видаляється разом із пробілом перед нею;
- нова властивість додається після останньої властивості в рядку, перед тілом `{ … }` чи коментарем (новий підпис зв’язку розміщується відразу після цільового елемента, на місці для підписів);
- теги, які ви залишили, не переміщуються, а нові додаються в кінці.

Коментарі, вирівнювання, тіло елемента й усе інше у файлі залишаються без змін. Якщо змінити технологію в інспекторі, рядок

```
    web = container "Web app" shape rect tech "React" tag "edge"  // storefront
```

перетвориться на

```
    web = container "Web app" shape rect tech "Vue" tag "edge"  // storefront
```

## Корисно знати

- **По одному об’єкту за раз.** Для редагування виберіть один елемент або зв’язок; якщо вибрано кілька, панель показує лише їх кількість. Подвійне клацання лінії, як і раніше, редагує підпис на місці.
- **Ідентифікатори елементів не змінюються.** Інспектор редагує відомості про елемент, а не його місце в моделі. Щоб змінити ідентифікатор, перенести елемент до іншого батьківського елемента чи додати порти, відредагуйте текст. Виняток — ідентифікатор зв’язку, який змінюється через Name.
- **Зв’язки ігнорують `shape` і `description`.** Інспектор їх не пропонує, а в тексті для них з’являється попередження.
- **Види та фігури мають імена.** Назва виду чи фігури з пробілами або недопустимими розділовими знаками відхиляється з поясненням у рядку стану; нічого не записується.
- **Ключі стилів** не можуть містити `=` або `;`, а значення — `;`, як і в тексті.
- **Значення, яке буде відхилено, обводиться червоним** ще під час введення, а підказка поля
  пояснює чому: Id, що не є назвою або вже зайнятий, вид чи форма, що не є назвою, ключ стилю з `=`
  або `;`, рядок спільних стилів, який не читається або не стосується елемента, і назва зв’язку, що
  не є назвою або вже зайнята. Обведення зникає, щойно значення стає правильним.
- **Вигляд цілого виду** краще визначати в блоці `style`, а не в полі Style кожного елемента. Поле Shared styles інспектора редагує блоки, застосовні до елемента (див. [Стилі та теми на полотні](styles-and-themes.md)).
- **Де це доступно:** у вебзастосунку та застосунках для macOS і Linux (GTK). У застосунку для Windows інспектора поки немає.
