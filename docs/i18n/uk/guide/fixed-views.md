# Малювання вручну у фіксованих поданнях

Більшість подань компонується автоматично: ви визначаєте, що до них входить, і за бажанням коригуєте розташування вказівками на кшталт `pin db below web`. Але іноді потрібно навпаки: кожен блок саме там, де ви його поставили, вибраного вами розміру, а лінії згинаються там, де ви вказали. Для цього є `layout fixed`. Його використовують діаграми, імпортовані з draw.io, і його можна застосувати в будь-якому власному поданні:

```
view checkout {
  include *
  layout fixed
  pin web at 40, 40 size 160, 70
  pin db at 320, 200
  route "writes" via 380, 90
}
```

`pin … at X, Y` ставить верхній лівий кут блока в задану точку, а `size W, H` визначає його ширину й висоту (без цього блок зберігає розмір, потрібний для підпису). `route "id" via X, Y …` перелічує точки згину лінії за [ідентифікатором зв’язку](relationships.md#ідентифікатори-звязків). Елементи без `pin` вишиковуються в ряд під закріпленими.

Усе це можна описати текстом, але на полотні можна й просто малювати.

## Переміщення

Перетягніть блок, щоб його перемістити. У фіксованому поданні він залишається точно там, де ви його відпустили, з Option чи без, а його рядок `pin … at` оновлюється відповідно до нової позиції. Раніше заданий розмір зберігається.

## Зміна розміру

Виберіть один блок, і на його кутах з’являться чотири квадратні маркери. Перетягніть один із них, щоб змінити розмір: протилежний кут залишиться на місці, а під час перетягування над блоком відображатиметься новий розмір. Блоки не зменшуються нижче 10 × 10.

Коли ви відпустите маркер, до `pin` блока буде записано нові позицію та розмір:

```
  pin web at 40, 40   // storefront
```

перетвориться на

```
  pin web at 40, 40 size 180, 82   // storefront
```

## Згинання ліній

Виберіть одну лінію, і на ній з’являться маркери:

- круглий маркер на кожній **точці згину**: перетягніть його, щоб перемістити згин;
- менший, світліший маркер **посередині кожного відрізка**: перетягніть його, щоб додати там згин;
- перетягніть згин на пряму між сусідніми точками, щоб **видалити** його.

Коли ви відпустите маркер, `route` лінії міститиме всі її точки згину за порядком:

```
  route "writes" via 380, 90 380, 150
```

Наявні в маршруті `from` і `to` (де лінія виходить із початкового й входить до кінцевого блока) зберігаються. Якщо не залишилося ані точок згину, ані `from` чи `to`, маршрут видаляється й лінія знову малюється прямою.

Маршрут неіменованого зв’язку вказується через похідний ідентифікатор, наприклад `route "web->db"`. Він змінюється, якщо змінити кінцеві точки зв’язку або видалити паралельний зв’язок, і тоді маршрут перестає діяти. Тому, якщо задаєте форму лінії вручну, [дайте зв’язку ім’я](relationships.md#коли-варто-назвати-звязок): `writes = web -> db`.

## Як змінюється текст

Як і кожна правка на полотні, це невелика зміна у файлі й один крок скасування, спільний із текстовим редактором (⌘Z з будь-якого боку її скасує):

- наявний `pin` або `route` переписується **на місці**; коментар після нього зберігається, а в поданні системи ім’я залишається таким, як ви його записали (`pin web`, а не `pin shop.web`);
- новий `pin` або `route` додається після інших рядків подання;
- координати округлюються до цілих чисел.

## Корисно знати

- **Точки згину є лише у фіксованих поданнях.** В автоматично компонованих поданнях немає маркерів згину: лінії визначає алгоритм. Змінювати розмір блоків і повертати їх можна в усіх поданнях; див. [Зміна розміру й обертання](resize-and-rotate.md). Додайте `layout fixed` до подання, щоб малювати вручну, або продовжуйте керувати компонуванням через вказівки.
- **По одному об’єкту за раз.** Маркери з’являються, коли вибрано рівно один блок чи одну лінію.
- **Ортогональні лінії** (`edgeStyle=orthogonalEdgeStyle`) зберігають прямі кути: після переміщення згину лінія отримує додаткові кути, потрібні для збереження ортогональності.
- **Де це доступно:** у вебзастосунку й застосунках для macOS, Linux (GTK) та Windows.
