# Приклади

У кожному застосунку є приклади діаграм, які можна відкривати, вивчати та змінювати. У macOS, Linux і Windows їх можна знайти в меню **File › Examples**, а у вебзастосунку — у списку **Examples…** на панелі інструментів. Вибраний приклад відкривається як новий документ без назви. Ваші зміни не зачіпають оригіналу; щоб їх зберегти, дайте документу власну назву.

| Приклад | Що показує |
| --- | --- |
| `bpmn-01-order-process` | Процес BPMN в одному пулі з двома доріжками: початкова подія-повідомлення, користувацькі, відправні, ручні та сервісні завдання, виключний і паралельний шлюзи, гранична подія-таймер, вихід даних |
| `bpmn-02-claim-collaboration` | Взаємодія двох пулів BPMN із потоками повідомлень, подієвим шлюзом, завданням бізнес-правила, сховищем даних і текстовою анотацією |
| `c4-01` … `c4-04` | Діаграми систем і контейнерів C4, групи, примітка довільної форми |
| `flow-01` … `flow-04` | Блок-схеми з розгалуженнями та циклами |
| `uml-01-class-library` | Діаграма класів UML: атрибути й операції, інтерфейс, абстрактний клас, успадкування, реалізація, композиція, агрегація, кратності |
| `uml-02-sequence-checkout` | Діаграма послідовності UML: активації, рамки `loop` і `alt`, відповіді, асинхронне повідомлення, примітка |
| `uml-03-activity-order` | Діаграма діяльності UML: початковий і кінцевий вузли, вузли рішення та злиття, вузли поділу й синхронізації |
| `uml-04-state-order` | Автомат станів UML: переходи з подіями, захисними умовами й діями, складений стан |
| `uml-05-use-case-shop` | Діаграма варіантів використання UML: актори, межа системи, «include» та «extend», узагальнення акторів |
| `uml-06-component-shop` | Діаграма компонентів UML: компоненти, надані інтерфейси у вигляді кружечків на ніжці, потрібні інтерфейси |

Ці приклади — файли `.draw` з каталогу `corpus/` репозиторію. Вони також слугують документами для тестів і вимірювання продуктивності: кожен має розбиратися без попереджень, а всі його подання — компонуватися з дотриманням усіх вказівок.

## Як побудовано приклади UML і BPMN

У DiaDraw немає окремих типів діаграм UML чи BPMN; у прикладах використано звичайний DSL:

- **Діаграми класів** використовують вид `class` із `prop "uml.attributes"` і `prop "uml.methods"` (один член класу на рядок, роздільник `\n`) та `prop "stereotype"`. Кратності задаються властивостями зв’язку `prop "uml.sourceMultiplicity"` і `prop "uml.targetMultiplicity"`. Типи ліній (успадкування, реалізація, композиція тощо) задаються блоками стилів зв’язків за тегом із порожнистими й заповненими [закінченнями ліній](line-styles.md).
- **Діаграми послідовності** — це подання `layout sequence` (див. [довідник DSL](../dsl.md#подання-послідовності)).
- **Діаграми діяльності й станів** використовують базові фігури: `circle` для початкових і кінцевих вузлів, `bar` для поділу й синхронізації, `rhombus` для рішення й злиття, `rounded` для станів.
- **Діаграми варіантів використання** зображують акторів через `shape actor`, а варіанти використання — через `shape ellipse` всередині елемента `system`, який відображається як межа системи.
- **BPMN** використовує вбудовану бібліотеку `bpmn` (`use "bpmn@^1" as bpmn`) для подій, завдань, шлюзів і даних. Пули та доріжки зображуються фігурами `swimlane` у [фіксованому поданні](fixed-views.md), як і під час компонування процесу в інструментах BPMN. Гранична подія закріплена на краю свого завдання й має `prop "bpmn.attachedTo"`, щоб під час експорту в BPMN зберігалася прив’язка.
