# Бібліотеки фігур

Бібліотека — це іменований набір із номером версії, що містить **фігури** (рисунки), **складені фігури** (побудовані з інших фігур), **види** (види елементів, не вбудовані в DSL) та **фрагменти** (частини вихідного тексту DiaDraw для вставлення), а також **відповідники** назв з інших інструментів. Через бібліотеки розширюються можливості DiaDraw: плагін — це бібліотека. Документи називають потрібні бібліотеки, а середовища виконання їх знаходять. Відображення та імпорт ніколи не звертаються до мережі.

```
use "c4@^1"
use "aws-icons@^2.1" as aws

model {
  user = person "User" shape c4.person
  fn = component "Handler" tech "Node" shape aws.lambda
  user -> fn
}
```

- `use "<name>[@<range>]" [as <alias>]` ставиться перед моделлю. Без `as` псевдонімом стає останній сегмент імені зі сторонніми символами, заміненими на `_` (`@acme/cloud-shapes` → `cloud_shapes`). Псевдоніми мають бути унікальними в межах документа.
- `shape <alias>.<shape>` посилається на звичайну або складену фігуру бібліотеки. Якщо середовище не знаходить фігури, елемент малюється звичайною фігурою свого виду, а `diadraw check`, `diadraw render` і редактор видають попередження.
- `<id> = <alias>.<kind>` оголошує елемент виду, доданого бібліотекою (див. [Види елементів](#види-елементів)). Невідомий вид малюється як блок із таким самим попередженням.
- Діапазони версій відповідають semver: `^1`, `~1.2`, `1.x`, `>=1.2 <2`, `1.2 - 1.6`, `^1 || ^2`, точні версії.

## Пошук версії

Для `use` версія визначається в такому порядку:

1. Версія, зафіксована в `diadraw-lock.json` для точного `name@range` (найближчий файл фіксації в каталозі документа чи вище), якщо ця версія є в кеші.
2. Найвища версія в кеші, що відповідає діапазону.
3. Найвища вбудована версія, що відповідає діапазону.

Кеш розташовано в `$DIADRAW_CACHE`, інакше в `$XDG_CACHE_HOME/diadraw/libraries`, інакше в `~/.cache/diadraw/libraries`. Він містить по одному пакунку JSON на версію. На цьому етапі нічого не завантажується: якщо бібліотеки немає в жодному з цих місць, з’явиться повідомлення, що її не встановлено. У вебзастосунку є лише вбудовані бібліотеки.

## Команди

```bash
diadraw lib init shapes --name team-shapes   # manifest, an example shape and fragment, README
diadraw lib build shapes                     # check and build → shapes/dist/library.json
diadraw lib pack shapes                      # → shapes/dist/team-shapes-0.1.0.ddlib and its integrity
diadraw lib add shapes/dist/team-shapes-0.1.0.ddlib   # install into the cache, pin in diadraw-lock.json
diadraw lib add https://example.com/libs/aws-icons-2.1.0.ddlib
diadraw lib add c4@^1                        # pin a built-in (or cached) library
diadraw lib install                          # make the cache hold everything the lockfile pins
diadraw lib list                             # built-in and installed libraries
diadraw lib build --drawio stencils.min.js --set aws4,flowchart -o libs
```

`add` приймає каталог бібліотеки, файл `.ddlib` або пакунок `.json`, URL `http(s)` чи `name[@range]` вбудованої або кешованої бібліотеки. Команда виводить рядок `use` для вставлення. Лише `add` та `install` використовують мережу, і тільки для URL, переданих у `add` або записаних у файлі фіксації. `install` звіряє кожен пакунок зі значенням `integrity` (`sha256-…` канонічного JSON пакунка) та зафіксованою версією.

Файл фіксації `diadraw-lock.json` слід додавати до системи контролю версій:

```json
{
  "lockfileVersion": 1,
  "libraries": {
    "c4@^1": { "version": "1.0.0", "resolved": "builtin", "integrity": "sha256-…" },
    "team-shapes@^0.1.0": {
      "version": "0.1.0",
      "resolved": "libs/team-shapes-0.1.0.ddlib",
      "integrity": "sha256-…"
    }
  }
}
```

`resolved` — це шлях відносно файла фіксації, URL, `builtin` або `cache:<name>@<version>` для бібліотеки, яка існувала лише в локальному кеші (і яку `install` не зможе відновити деінде).

## Маніфест

Каталог із вихідними файлами бібліотеки містить `diadraw-library.json`:

```json
{
  "name": "team-shapes",
  "version": "0.1.0",
  "description": "Shapes for our services",
  "license": "MIT",
  "source": { "kind": "original" },
  "shapes": {
    "gateway": {
      "label": "API gateway",
      "category": "Edge",
      "kind": "component",
      "svg": "shapes/gateway.svg",
      "width": 48,
      "height": 48,
      "keywords": ["api", "ingress"]
    },
    "store": { "label": "Store", "base": "cylinder", "kind": "database" }
  },
  "kinds": {
    "edge": {
      "label": "Edge service",
      "description": "Anything that terminates client traffic",
      "shape": "gateway",
      "stereotype": "edge"
    },
    "topic": { "label": "Topic", "base": "hexagon", "fill": "#fde68a", "stroke": "#b45309" }
  },
  "composites": {
    "gateway_with_store": {
      "width": 120,
      "height": 48,
      "parts": [
        { "shape": "gateway", "x": 0, "y": 0, "width": 48, "height": 48 },
        { "shape": "store", "x": 72, "y": 0, "width": 48, "height": 48 }
      ]
    }
  },
  "fragments": {
    "edge": {
      "label": "Gateway in front of a service",
      "params": [{ "name": "service", "default": "api" }],
      "text": "fragments/edge.draw"
    }
  },
  "mappings": { "drawio": { "mxgraph.team.gateway": "gateway" } },
  "themes": {
    "corporate": {
      "extends": "default",
      "background": "#fafafa",
      "edge": "#4a4a4a",
      "nodes": { "system": { "fill": "#aa0000", "stroke": "#7a0000", "text": "#ffffff" } }
    }
  },
  "dependencies": { "c4": "^1" }
}
```

| Поле | Значення |
| --- | --- |
| `name`, `version` | ім’я у стилі npm (малі літери, `-._`, необов’язкова область `@scope/`), версія semver |
| `license` | вираз SPDX для рисунків; `licenseNotes` — додаткові умови |
| `source` | походження рисунків: `original`, `drawio-stencils`, `plantuml-stdlib`, `svg`, `other`, з полями `url`, `commit`, `sets` |
| `shapes` | id (ідентифікатор) → `svg` (шлях до файла чи вбудована розмітка) або `base` (базова фігура візуалізатора), `label`, `category`, `kind` для нових елементів, розмір, `keywords`, `style` |
| `composites` | фігура з `parts`, кожна з яких — фігура цієї бібліотеки (або `dep.shape` із залежності), розміщена в межах складеної фігури |
| `kinds` | id (ідентифікатор) → вид елемента: `shape` (звичайна чи складена фігура цієї бібліотеки або `dep.shape`) чи `base`, `fill`, `stroke`, `fontColor`, `stereotype`, `label`, `description`, `category`, `keywords` |
| `fragments` | текст DiaDraw (файл `.draw` або вбудований текст), що вставляється в `model { … }`; `${param}` підставляє параметр, `${alias}` — псевдонім, під яким використовується бібліотека |
| `open` | приймати будь-яке ім’я фігури й малювати її як `base` (для наборів піктограм без переліку імен) |
| `mappings` | для кожного формату (`plantuml`, `plantuml-include`, `plantuml-local`, `structurizr`, `drawio`, `bpmn`): зовнішнє ім’я → ідентифікатор фігури |
| `themes` | id → тема як у `theme … { … }` ([dsl.md](dsl.md#власні-теми)): `extends` (вбудована тема, тема цієї бібліотеки або `dep.theme`), ключі теми, `nodes` |
| `dependencies` | бібліотеки, на які спираються складені фігури: `name` → діапазон версій |

`kind` звичайної чи складеної фігури (вид елемента, який палітра для неї додає) позначає власний вид бібліотеки, якщо в ній є такий, а інакше — вбудований вид.

## Види елементів

DSL має кілька вбудованих видів (`person`, `system`, `container`, `component`, `database`, `process`, `decision`, `start`, `end`, `note`, а також види UML і BPMN, які використовують засоби імпорту). Бібліотека додає нові в `kinds`, а документи звертаються до них через псевдонім:

```
use "team-shapes@^0.1" as team

model {
  lb = team.edge "Load balancer"
  orders = team.topic "Orders"
  lb -> orders
}
```

Вид задає вигляд своїх елементів; усе інше (підписи, `tech`, дочірні елементи, порти, зв’язки, подання) працює так само, як для будь-якого елемента.

- **Фігура.** `shape` малює елементи рисунком бібліотеки (з розміром і підписом, як у посилання `shape`); `base` — базовою фігурою візуалізатора (`hexagon`, `cylinder` тощо). Власна `shape` елемента має перевагу.
- **Кольори.** `fill`, `stroke` і `fontColor` замінюють типові кольори вузлів теми для цього виду. Власний `style` елемента має перевагу, а елементи `external` зберігають кольори зовнішніх елементів.
- **Стереотип.** Елемент цього виду з дочірніми елементами малюється як рамка з підписом `Name [stereotype]`.
- **Де їх знайти.** Мовний сервер пропонує види `alias.` після `=` і попереджає про види, яких немає в бібліотеці (біля назви виду); `diadraw check` та `render` видають такі самі попередження. У вебпалітрі види перелічено під _Kinds_: вибір одного з них додає оголошення елемента відповідного виду.

У моделі види зберігають повні імена (`team.topic`), тож під час виведення документа вони не губляться.

`lib build` читає файли SVG, очищує їх (жодних скриптів, обробників подій, сторонніх об’єктів або зовнішніх посилань; ідентифікатори отримують префікс для кожної фігури, щоб піктограми на сторінці не конфліктували), вбудовує все в один пакунок (`format: "diadraw-library"`, `formatVersion: 1`) і перевіряє, чи кожен фрагмент синтаксично коректний. `.ddlib` — це такий пакунок, стиснений gzip.

## Ліцензії

Кожна бібліотека має ліцензію, яку перевіряють `lib build`, `lib add` і генератор вбудованих бібліотек:

| Статус | Умова | Наслідок |
| --- | --- | --- |
| `allowed` | усі складники хоча б однієї альтернативи є в списку дозволених (MIT, MIT-0, Apache-2.0, BSD-2/3-Clause, ISC, 0BSD, CC0-1.0, CC-BY-4.0, Unlicense), без додаткових умов; або це оригінальна робота цього проєкту | може постачатися з DiaDraw |
| `restricted` | дозволені ліцензії з `licenseNotes` | попередження; дозволено локальне використання, не постачається |
| `disallowed` | у кожній альтернативі є умови некомерційності, заборони похідних творів чи копілефту (CC-BY-NC/ND, GPL, AGPL, LGPL, SSPL, BUSL) | `lib build` завершується помилкою |
| `unknown` | усе інше | попередження |

З `assets/builtin/` до вбудованих потрапляють лише бібліотеки зі статусом `allowed`. Єдиний виняток — набори трафаретів draw.io: ухвалено рішення постачати їх зі статусом `restricted` (див. нижче й у `docs/decisions.md`).

## Вбудовані бібліотеки

Вихідні файли містяться в `assets/builtin/`; `node tools/gen/builtin_libraries.mjs` (після `npm run build -w @diadraw/wasm`) збирає їх за допомогою ядра й записує `src/library/src/builtin_libraries.inc`, який вбудовується в ядро під час компіляції.

- **`c4`**: людина, програмна система, контейнер, компонент, база даних, черга, веббраузер і мобільний застосунок; кожен також у зовнішньому варіанті, якщо C4 його передбачає. Є складена фігура «сервіс із базою даних», фрагменти «контекст системи» та «вебзастосунок, API й база даних». Відповідники: макроси C4-PlantUML (`Person`, `System_Ext`, `ContainerDb`, `ComponentQueue` тощо) і фігури Structurizr (`WebBrowser`, `Cylinder`, `Pipe` тощо). Рисунки оригінальні.
- **`drawio-*`**: 204 набори трафаретів draw.io з обмеженнями; див. [Трафарети draw.io](#трафарети-drawio).
- **`plantuml-aws`, `plantuml-azure`, `plantuml-gcp`, `plantuml-kubernetes`, `plantuml-tupadr3`, `plantuml-office`, `plantuml-cloudinsight`, `plantuml-logos`, `plantuml-material`, `plantuml-elastic`, `plantuml-osa`, `plantuml-cloudogu`, `plantuml-ibm`, `plantuml-archimate`**: набори піктограм стандартної бібліотеки PlantUML у вигляді відкритих бібліотек. За відповідниками `plantuml-include` і `plantuml-local` засіб імпорту PlantUML розпізнає `!include <awslib/…>`, звичні URL і копії, додані до проєкту. Макрос піктограми, як-от `Lambda(fn, "Handler")`, імпортується як `shape aws.Lambda` з `use "plantuml-aws@^1" as aws`. Самі піктограми не включено (їхні ліцензії різняться), тому ці фігури зображуються як блоки піктограм.
- **`bpmn`**: фігури BPMN 2.0 в оригінальному оформленні. Представлено всі позиції подій (початкова, початкова без переривання, початкова подієвого підпроцесу, проміжна приймальна, гранична без переривання, проміжна породжувальна, кінцева) з усіма дозволеними для них маркерами BPMN; завдання всіх типів, викличні дії, підпроцеси, подієві підпроцеси, транзакції та спеціальні підпроцеси — без маркера або з маркером циклу, паралельних чи послідовних множинних екземплярів або компенсації; усі шлюзи; об’єкти даних, колекції, входи, виходи й сховища; повідомлення, текстові анотації, групи, розмови та завдання хореографії. Підпис дії залишається всередині фігури. Також є складена фігура «завдання з таймером» і фрагменти «цикл погодження» та «завдання з обмеженням часу». Відповідники `bpmn` задають фігуру для кожного типу елемента BPMN. Генерується за допомогою `tools/gen/bpmn_library.mjs`.

## Трафарети draw.io

Усі набори трафаретів draw.io постачаються як вбудовані бібліотеки з назвами `drawio-<set>` (`drawio-aws4`, `drawio-azure`, `drawio-cisco19`, `drawio-flowchart` тощо): 204 набори, 9 088 фігур із draw.io 32.6.9. Користуйтеся ними як будь-якою іншою бібліотекою:

```
use "drawio-aws4@^32" as aws4

model {
  fn = component "Handler" shape aws4.lambda_function
}
```

**На них діють обмеження.** Сам draw.io має ліцензію Apache-2.0, але його трафарети не можна використовувати в продуктах Atlassian або на Atlassian Marketplace, розповсюджувати для використання з ними чи включати до них без письмового дозволу. На набори постачальників (AWS, Azure, GCP, Cisco, IBM тощо) поширюються їхні умови використання торговельних марок. Див. `assets/NOTICE`. `diadraw lib list` і вебпалітра позначають усі набори як обмежені.

Вони зберігаються стисненими gzip в `assets/drawio/` і завантажуються на вимогу. Лише коли документ використовує набір або палітра відкриває його, із файла читається набір (у нативних середовищах і середовищах WebAssembly із файловою системою, заданою через `setFileSystem(fs, { drawio })`) або він завантажується й додається через `addLibrary` (у вебзастосунку).

Засіб імпорту draw.io малює трафаретні фігури за допомогою цих бібліотек із кольорами заливки й контуру комірки (включно з плитками піктограм ресурсів). Перетворення відповідає mxStencil: контури, прямокутники, заокруглені прямокутники та еліпси із заливкою, обведенням, кольорами, штрихами, прозорістю та збереженням/відновленням стану. Текст, зображення й вкладені трафарети не малюються, а фігури, які draw.io малює програмно, не є трафаретами.

Повторна генерація із зафіксованої версії (`DRAWIO` у скрипті):

```bash
npm run build -w @diadraw/wasm
node tools/gen/drawio_stencils.mjs                   # downloads the pinned files
node tools/gen/drawio_stencils.mjs --from ../drawio  # or a local checkout
```

`diadraw lib build --drawio <stencils.min.js|set.xml> -o <dir>` і надалі перетворює інші версії чи окремі набори на окремі бібліотеки.

## Де використовуються бібліотеки

- **Командний рядок**: `render` і `check` знаходять бібліотеки документа; `render` малює бібліотечні фігури.
- **Мовний сервер**: пропонує доповнення імен бібліотек в `use "…"`, фігур після `shape` (усіх, якщо їх не більше 400, інакше спочатку псевдоніми) і префіксів `alias.`, бібліотечних видів після `=`, а також фрагменти для вставлення в `model { … }` із місцями для параметрів. Про відсутні бібліотеки, невідомі фігури та види видаються попередження.
- **Вебредактор**: кнопка **Shapes** відкриває палітру звичайних і складених фігур, видів та фрагментів вбудованих бібліотек із пошуком за ім’ям і ключовим словом. Клацання фігури додає елемент із цією фігурою (і `use` бібліотеки, якщо його ще немає в документі) однією дією, яку можна скасувати. Клацання фрагмента вставляє його текст у кінець моделі.
- **Теми**: `theme alias.name` вибирає бібліотечну тему; `RenderOptions.themes` (`LibrarySet::theme_resolver()`) знаходить її, а інструмент командного рядка та мовний сервер попереджають про відсутню в бібліотеці тему.
- **Візуалізатор**: `RenderOptions.shapes` знаходить за посиланнями рисунки, які відображаються з підписом унизу; `RenderOptions.kinds` визначає фігуру й кольори бібліотечних видів; `create_measure(theme, shapes, kinds)` добирає відповідні розміри. `LibrarySet::renderer()` надає обидва засоби пошуку.
